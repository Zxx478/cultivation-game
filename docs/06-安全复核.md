# 《荒天纪》v1.5 · 安全复核（聚焦式）

> 范围：交付前对新增游戏层（FastAPI + SQLite + Jinja2 + 原生 JS）做聚焦复核，
> **不是**全量渗透测试。方法：静态扫描 + 关键边界用例 + 人工审计。
> 结论可复现：本文所有检查命令均已实际执行。

## 1. 检查项与结论

| # | 检查面 | 方法 / 命令 | 结论 |
|---|---|---|---|
| 1 | SQL 注入 | `grep -rn 'execute(f"' app/`、审计 `game_repository._trim`、`repository._ensure_character_columns` | **无注入面**：两处动态 SQL 的表名/列名均来自代码内常量（`event_log/milestone_log`、`_CHARACTER_COLUMNS`），用户输入只走 `?` 参数 |
| 2 | XSS | `grep -rn innerHTML app/web/static/js`；Jinja2 `select_autoescape(["html","xml"])` | **通过**：前端无 `innerHTML` 通道，全部 `createElement/textContent`；角色名等用户输入不出现在 HTML 拼接路径 |
| 3 | 存档伪造 | 篡改 1 字节后 `POST /saves/import` | **拒绝**：`checksum` 不匹配 → `4020`，且不落库（有测试 `test_export_import_and_tamper`） |
| 4 | 导入体大小 | `MAX_IMPORT_BYTES = 2MB` | 超限拒绝 |
| 5 | 密钥管理 | 移除仓库内固定默认密钥；`_secret()` 优先环境变量，否则生成 `data/.save_secret`（64 hex） | **已加固**；跨设备导入需两端同一 `SAVE_SIGN_SECRET` |
| 6 | 随机可预测 | 验收「同一 seed+counter 同结果」；`rng_seed` 不出现在 `/state` | 通过；`/state` 断言无 `rng_seed` |
| 7 | 越权读写 | 所有写接口按 `meta.active_char_id` 解析角色，**不接受前端传 character_id** | 单机单角色，天然消除 IDOR |
| 8 | 危险函数 | `grep -rn 'eval(\|exec(\|os.system\|subprocess'` | 无 |
| 9 | 静态资源 | `StaticFiles(directory=...)` 目录为内部常量 | 无路径穿越 |
| 10 | 并发写 | `character.version` 乐观锁；读档带 `expected_version` → 409/4004 | 通过（单人单写，冲突主要来自刷新重放） |

## 2. 已接受的残留风险（按设计，非缺陷）

| 项 | 影响 | 处置 |
|---|---|---|
| 无登录 / 无多用户 | 同一端口可被同机其他进程调用 | 只绑 `127.0.0.1`；**不要**暴露公网。README 已警示 |
| 无 HTTPS | 本地回环无中间人 | 单机定位；公网部署需自行加反代 + TLS |
| 自动槽与手动槽无密码保护 | 同机用户可读档 | 单机作品，非多租户 |
| `techniques/learn` 可学习任意已配置功法 | 破坏经济（非安全边界） | MVP 功法主要经任务/兑换/奇遇发放；该端点留作兼容，见「后续待办」 |

## 3. 建议（后续）

1. 若要公开部署：加简单 token/登录 + 限流，并把 SQLite 换服务端 DB。
2. `techniques/learn` 增加 `tech_unlock:<id>` 标记门（与发放点对齐）。
3. 给 `/saves/import` 增加结构白名单校验（当前已校验四项，但未逐字段限长）。
