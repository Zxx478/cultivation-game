# 《荒天纪》v1.5 · 实现说明

> 面向后续维护者：整体结构、关键逻辑与对接点。数值口径以 `docs/04-系统设计-v1.5.md` 为准。

## 1. 分层与依赖

```
web（Jinja2 + 原生 JS）  →  api（game_router / sect_router）
                                   ↓
services（事务边界、桥接既有子系统、发奖）
        ↓                ↓
   domain（纯逻辑）   content（YAML → 冻结索引）
        ↓                ↓
      core（rng/clock/errors）      db（game.sql + game_repository + 既有 repository）
```

- `domain/` 不 import DB/FastAPI，可被单测直接驱动。
- `content/` 启动期加载 16 个 YAML 并做 20+ 项校验，失败即拒绝启动。
- `db/` 中既有 `repository.py` 仍是宗门子系统的权威；`game_repository.py` 只做新增表与快照。

## 3. 关键逻辑

### 3.0 启动流程（首页 → 创角 → 主界面）

- 启动后默认进首页 `#/home`（`stage=home` 时隐藏顶栏/侧栏/底部 Tab）。
- 首页 `GET /meta` 拉取内容版本、行动基础耗时、境界表；`GET /saves` 列出 3 手动 + 1 自动槽。
  - 「开始游戏」→ `#/creation`（无角色时创建；有角色时可重开一世，旧角色仍留存档）。
  - 「继续修行」→ `#/main`；存档槽「读取」→ `POST /saves/load` 后 `GET /state` 恢复。
- 创角进入只调 `GET /bootstrap/candidate`（不消耗重掷次数），点「重掷」才 `POST /bootstrap/reroll`（最多 3 次，第 4 次 4002）。
- 创角提交成功后清掉候选、写入自动槽、`router.go('main')`，无断裂。

### 3.1 修为与升级

```
Exp(L) = floor(100 × L^1.78 × K(realm))
ExpRate = (5 + wis×0.8) × (1+0.35×(R-1)) × 功法 × 体质 × 环境 × 心境 × 状态 × 方向 × 1.5
闭关修为 = floor(ExpRate × days)
```

- `apply_exp` 的 `cap_level` 取**当前境界的 level_end**，所以 Lv.9 不会自动升到 Lv.10，必须走突破。
- 单次最多连升 5 级，超出进 `exp_overflow`，总量守恒（有测试断言）。

### 3.2 行动 → 事件 → 战斗

`POST /action` 单事务内：更新 `age_days` → 行动产出 → 35% 事件判定（散修 38.5%）→
若触发则写 `pending_event` 并中断持续闭关；历练/切磋则创建 `combat_session` 并返回战斗视图。
事件必须 `POST /event/choose`（带 `instance_id`）才清算，防刷新重放。

### 3.3 战斗

- `domain.combat.step(state, action, rng)` 纯函数，输入输出都是可 JSON 序列化 dict。
- 服务端每次落 `combat_session` + `rng_counter`，刷新后 `GET /combat` 原样恢复。
- 结束分支：`victory`（发奖 + 击杀标记 + 禁地回调）、`defeat`（还魂丹或 `dead`）、
  `escaped/timeout`（气血灵力写回角色）。

### 3.4 宗门 / 散修 / 禁地对接

| 关注点 | 实现 |
|---|---|
| 身份权威 | 仍是 `sect_member` / `sect_reputation` / `sansxiu_wallet`；`character.sect_id/path_id` 只是镜像 |
| 任务 | `QuestService.take/complete(today_day=age_days, game_year=game_year(age_days))`，奖励再由 `GrantService` 同步到角色 |
| 兑换 | `ExchangeService.check_and_exchange` 扣贡献，随后由桥接层真正发功法/装备/道具 |
| 禁地 | 只读前置校验 → 扣进入耗时 → Boss 战 → 胜利后才 `ForbiddenLandService.enter()` 扣贡献/置首通，再发放 |
| 散修转宗门 | 入宗时 `general_contribution × 0.5` 转入宗门贡献，钱包清零（一次性 flag 防重复） |

### 3.5 存档

- 快照 = `character` + 6 张角色子表 + 4 张宗门表；`save_slot` 不设 FK，独立于角色。
- 读档顺序固定：角色 UPDATE（version 校验）→ 清重灌子表 → upsert 宗门表 → 删战斗会话。
- 导入新建角色并占用一个空手动槽；`checksum` 用 HMAC-SHA256，密钥来自环境变量或 `data/.save_secret`。

## 4. 启动自检（fail-fast）

`content/validators.py` 断言：数量（12 境/41 功法/15 道具/20 区域/20 事件/19 主线/6 宗门/24 宗门功法/10 禁地/5 体质）、
权重和 10000、跨文件引用闭合、主线等级并集覆盖 1–18、每事件选项带负面代价、散修权重和 100。

## 5. 测试策略

- 域层：公式与状态机（最高优先级，全部纯函数）。
- 服务/接口：`TestClient` + 内存库，覆盖错误码与 HTTP 映射。
- Web：静态资源与 DOM 契约（`data-pane` 数量、无外链）。
- 手动：Playwright 端到端冒烟（创角→闭关→事件→任务→突破→宗门→战斗→存档）。
